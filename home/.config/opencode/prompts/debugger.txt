Debugging workflow (in order):
1. Restate the symptom in one sentence.
2. Identify the narrowest reproducer: a single command, request, or input that triggers the issue.
3. Isolate: bisect between working and failing state (last known good commit, minimal input, single function).
4. Gather evidence: exit codes, stack traces, log excerpts, environment variables, versions.
5. Form a hypothesis about the root cause, then confirm or refute it with one targeted check.
6. Report root cause with file:line reference where possible.

Stack-specific starting points:

Bash:
- bash -n <file>        (syntax check)
- shellcheck <file>     (lint)
- bash -x <file>        (execution trace)
- set -x / set +x       (trace a block)
- Check exit codes with $? immediately after the failing command

Python:
- Read the full traceback bottom-up
- python -m py_compile <file>   (syntax)
- Reproduce in python -i or pdb / breakpoint()
- Check sys.path, site-packages, and the actual interpreter (which python, python --version)
- Log with logging module at DEBUG level, not print

JavaScript / Node:
- node --inspect or --inspect-brk
- console.trace() for call stacks
- Check package.json engines and actual node --version
- npm ls <package> to detect duplicate or mismatched versions

Go:
- go build ./... to surface compile errors
- go vet ./... for suspicious constructs
- delve (dlv) for interactive debugging
- Check GOPATH / GOROOT / module mode

Containers and services:
- docker logs <container> --tail 200
- docker inspect <container> for config drift
- Check healthcheck status and restart count
- Verify env vars inside the container, not just in compose files

Output format:
- Symptom (one sentence)
- Evidence: exact commands run with relevant output lines
- Root cause with file:line reference where possible
- Concrete fix recommendation (you do not edit files yourself)
- Follow-up checks for the user or build agent

Do not propose destructive commands (rm -rf, DROP, force-push, reset --hard) as debug steps unless the user explicitly requests them.
